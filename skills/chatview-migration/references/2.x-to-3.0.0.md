# 2.5.x → 3.0.0

Applies if the app is on any 2.x version, after `references/2.x-to-2.5.0.md`.
The "after" code is written against the latest chatview. The documented iOS
minimum rose from 10.0 to 13.0.

The official migration guide (`doc/documentation.md`) covers only the
recorder settings and the text field actions. The first two changes below
are not in it, and the third is only half covered: the guide shows the action
buttons but not the removed flags or the two pitfalls. They break most apps.

## `RepliedMessageConfiguration.loadOldReplyMessage` is required

Search: `RepliedMessageConfiguration(`.

Any `RepliedMessageConfiguration` without it fails to compile. ChatView calls
it when the user taps a reply whose original message is not in the loaded
list.

Apps that never pass `ChatView.repliedMessageConfig` still compile, but
tapping a reply to an unloaded message now throws ("Please provide
`loadOldReplyMessage` ...") instead of doing nothing. Add the config.

After:

```dart
repliedMessageConfig: RepliedMessageConfiguration(
  loadOldReplyMessage: (messageId) async {
    // Fetch every message from messageId up to the oldest one loaded
    // (oldest first), then prepend them:
    final older = await fetchMessagesFrom(messageId);
    chatController.loadMoreData(older);
  },
),
```

The callback must load the message with that id. If it is still missing after
the callback returns, ChatView throws "Failed to find message with id"
(unhandled), so `(messageId) async {}` is not a safe placeholder. If the app
cannot load old messages, say so to the user instead of adding a no-op.

Avoid `chatController.replaceMessageList` here. It caches the current list,
and the cache is only cleared when a later `next` page overlaps it partially
(this departs from `doc/documentation.md`, which suggests `replaceMessageList`
for this callback).
Reverting (`revertToInitialMessageList`, `addMessage`,
`scrollToLastMessage`) keeps the cache, so each later send resets the list
to that snapshot and drops messages sent since.

## Pagination: `loadMoreData` and `isLastPage` changed type

Search: `loadMoreData:`, `isLastPage:`, `chatController.loadMoreData(`.

`loadMoreData` now receives the direction and the reference message (the
oldest loaded message for `previous`, the newest for `next`, with the default
`groupedListOrder`). `isLastPage` is a getter function,
not a `bool`.

Before:

```dart
ChatView(
  isLastPage: _isLastPage,
  loadMoreData: () async {
    final older = await fetchOlder();
    chatController.loadMoreData(older);
  },
  // ...
)
```

After:

```dart
ChatView(
  isLastPage: () => _isLastPage,
  loadMoreData: (direction, message) async {
    final page = switch (direction) {
      ChatPaginationDirection.previous => await fetchBefore(message.id),
      ChatPaginationDirection.next => await fetchAfter(message.id),
    };
    chatController.loadMoreData(page, direction: direction);
  },
  // ...
)
```

A `bool` variable passed to `isLastPage` must become a closure, so later
changes of the variable are seen. Apps that only page backwards can ignore
`next` (return without loading).

## Image picker flags replaced by text field actions

Search: `enableCameraImagePicker:`, `enableGalleryImagePicker:`,
`imagePickerConfiguration:` inside `SendMessageConfiguration(`.

The two flags were removed. Without `trailingActions` the field still shows
camera and gallery buttons, but:

- `SendMessageConfiguration.imagePickerConfiguration` is **no longer used** by
  the default buttons. Pass it to `CameraActionButton` /
  `GalleryActionButton` instead.
- The default buttons are disabled when `sendMessageConfig.textFieldConfig` is
  null (verified in `chatui_textfield.dart`). Always pass a
  `textFieldConfig`, even `const TextFieldConfiguration()`.

To hide a button or configure the picker, list the actions yourself. Custom
action buttons don't go through `onSendTap`: call the app's send handler.

Before:

```dart
sendMessageConfig: SendMessageConfiguration(
  enableCameraImagePicker: false,
  imagePickerConfiguration: ImagePickerConfiguration(imageQuality: 70),
),
```

After:

```dart
sendMessageConfig: SendMessageConfiguration(
  textFieldConfig: TextFieldConfiguration(
    trailingActions: (context, controller) => [
      GalleryActionButton(
        icon: const Icon(Icons.image),
        imagePickerConfiguration: const ImagePickerConfiguration(
          imageQuality: 70,
        ),
        onPressed: (path, replyMessage) {
          if (path == null || path.isEmpty) return; // picker cancelled
          onSendTap(
            path,
            replyMessage ?? const ReplyMessage(),
            MessageType.image,
          );
        },
      ),
    ],
  ),
),
```

`onSendTap` here is the same function the app passes to `ChatView.onSendTap`.
A custom button bypasses what the default buttons do: it skips the
`shouldSendImageWithText` staging, doesn't close the reply bar
(`ChatView.closeReplyMessageView(context)`) and doesn't scroll to the new
message (`chatController.scrollToLastMessage()`). Call them yourself if the
app needs that. To hide both buttons, return `[]`. `leadingActions` takes the same builder
for actions before the field; `OverlayActionButton` groups
`OverlayActionWidget`s behind a "+" button and `EmojiPickerActionButton`
opens the emoji sheet. The voice button is not part of the actions; keep
using `allowRecordingVoice`.

## Recorder settings moved to `RecorderSettings`

Search: `sampleRate:`, `bitRate:`, `iosEncoder:`, `androidEncoder:`,
`androidOutputFormat:`, `AndroidOutputFormat`, `AndroidEncoder.`.

chatview now uses audio_waveforms 2.x. `AndroidOutputFormat` no longer
exists (the encoder decides the format) and the `AndroidEncoder` values were
renamed.

Before:

```dart
voiceRecordingConfiguration: VoiceRecordingConfiguration(
  sampleRate: 44100,
  bitRate: 128000,
  iosEncoder: IosEncoder.kAudioFormatMPEG4AAC,
  androidEncoder: AndroidEncoder.aac,
  androidOutputFormat: AndroidOutputFormat.mpeg4,
),
```

After:

```dart
voiceRecordingConfiguration: const VoiceRecordingConfiguration(
  recorderSettings: RecorderSettings(
    sampleRate: 44100,
    bitRate: 128000,
    iosEncoderSettings: IosEncoderSetting(
      iosEncoder: IosEncoder.kAudioFormatMPEG4AAC,
    ),
    androidEncoderSettings: AndroidEncoderSettings(
      androidEncoder: AndroidEncoder.aacLc,
    ),
  ),
),
```

| `AndroidEncoder` (2.x) | 3.0.0+ |
|---|---|
| `aac` | `aacLc` |
| `he_aac` | `aacHe` |
| `aac_eld` | `aacEld` |
| `amr_nb` | `amrNb` |
| `amr_wb` | `amrWb` |
| `opus` | `opus` |
| `vorbis` | removed; use `opus` |

`IosEncoder` values are unchanged. `waveStyle`, `micIcon`, `stopIcon` and the
other `VoiceRecordingConfiguration` fields are unchanged.

## Voice message play/pause icons are builders

Search: `playIcon:`, `pauseIcon:`, `playerWaveStyle:` inside
`VoiceMessageConfiguration(`.

Before:

```dart
voiceMessageConfig: VoiceMessageConfiguration(
  playIcon: Icon(Icons.play_arrow),
  pauseIcon: Icon(Icons.pause),
  playerWaveStyle: PlayerWaveStyle(liveWaveColor: Colors.blue),
),
```

After:

```dart
voiceMessageConfig: VoiceMessageConfiguration(
  playIcon: (isMessageBySender) => const Icon(Icons.play_arrow),
  pauseIcon: (isMessageBySender) => const Icon(Icons.pause),
  outgoingPlayerWaveStyle: const PlayerWaveStyle(liveWaveColor: Colors.blue),
  inComingPlayerWaveStyle: const PlayerWaveStyle(liveWaveColor: Colors.blue),
),
```

The builders must return an `Icon` (not any `Widget`, despite the
CHANGELOG). `playerWaveStyle` still compiles but is deprecated.

## `Message.key` removed

Search: `message.key`, `.key.currentContext` on messages, `copyWith(key:`.

Messages no longer carry a `GlobalKey`. Identify messages by `id`. To scroll
to a replied message, the package scrolls to it itself (it no longer uses
`Message.key`) and calls `loadOldReplyMessage` when the original isn't loaded. `Message` also gained value equality:
two `Message` objects with equal fields are `==`.

## `ChatViewLocale` has 16 new required strings

Search: `ChatViewLocale(`, `ChatViewLocale.fromMap(`.

A hand-written `ChatViewLocale(...)` must add: `search`, `now`, `minAgo`,
`voice`, `typing`, `isVerb`, `areVerb`, `other`, `others`, `mute`,
`unmute`, `pin`, `unpin`, `deleteChat`, `noChats`, `noSearchResults`.
`ChatViewLocale.fromMap` compiles unchanged but sets every missing key to
`''`, so add the keys to the map. English values are in `ChatViewLocale.en`
(e.g. `minAgo: 'min ago'`, `typing: 'typing'`, `isVerb: 'is'`,
`areVerb: 'are'`).

## Behavior and type changes to check

- **Reactions on custom messages:** shown by default now. To keep the old
  look: `MessageConfiguration(showReactionsOnCustomMessages: false)`.
- **Non-nullable configs:** `ChatView.sendMessageConfig` and
  `typeIndicatorConfig` no longer accept `null` (omit them instead); same for `ChatViewStateConfiguration`'s
  `loadingWidgetConfig` / `errorWidgetConfig` / `noMessageWidgetConfig`, and
  `TypeIndicatorConfiguration.indicatorSize` / `indicatorSpacing` (defaults
  10 / 4).
- `ChatViewStateConfiguration` is a `final class`: app code can't extend it.
- `ChatController.messageStreamController` is `final` and a broadcast
  stream; it can't be reassigned.
- `TextFieldConfiguration.hideLeadingActionsOnType` (default `true`) only
  affects the new `leadingActions`.
- iOS: the documented minimum is 13.0. Set `platform :ios, '13.0'` in
  `ios/Podfile`.
