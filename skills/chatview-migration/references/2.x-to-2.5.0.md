# 2.0.x – 2.4.x → 2.5.0

Applies if the app is on 2.0.0 – 2.4.1. Apply the sections whose "from" range
contains the app's current version, in order. The "after" code is written
against the latest chatview.

## From < 2.1.0

### `SwipeToReplyConfiguration.animationDuration` removed

Search: `animationDuration:` inside `SwipeToReplyConfiguration(`.

Delete it; there is no replacement. New optional colors:
`replyIconProgressRingColor`, `replyIconBackgroundColor`.

### Recording icons are no longer swapped

Search: `micIcon:`, `stopIcon:` inside `VoiceRecordingConfiguration(`.

Before 2.1.0 the record button showed `stopIcon` while idle and `micIcon`
while recording. If the app swapped the two to compensate, swap them back:
`micIcon` = idle, `stopIcon` = recording.

## From < 2.3.0

### `ImageMessageConfiguration.onTap` receives the `Message`

Search: `onTap:` inside `ImageMessageConfiguration(`.

Before:

```dart
imageMessageConfig: ImageMessageConfiguration(
  onTap: (imageUrl) => openImage(imageUrl),
),
```

After:

```dart
imageMessageConfig: ImageMessageConfiguration(
  onTap: (message) => openImage(message.message), // the image URL or path
),
```

## From < 2.4.1

Models and `ChatController` moved to the `chatview_utils` package, which
`package:chatview/chatview.dart` re-exports. Dart SDK minimum: 3.4.0.

### Don't import package internals

Search: `package:chatview/src/`, `package:chatview_utils/`.

Replace every `package:chatview/src/...` import with
`package:chatview/chatview.dart`; the files moved. Don't add
`chatview_utils` as a dependency: chatview pins the exact version it needs.

### `ChatController.otherUsers` is read-only

Search: `otherUsers =`, `otherUsers.add(`, `otherUsers.remove`,
`extends ChatController`, `implements ChatController`.

`otherUsers` is now a getter that returns a **copy**: assigning fails to
compile, and `otherUsers.add(...)` compiles but changes nothing.

Before: `chatController.otherUsers.add(newUser);`

After: `chatController.updateOtherUser(newUser);` (adds the user, or replaces
the one with the same `id`). There is no remove method.

`ChatController` is a `base class`: an app subclass must be declared
`base class`, `final class` or `sealed class`, and can't `implements` it.

### `Message.statusNotifier` is read-only

Search: `statusNotifier.value =`.

Before: `message.statusNotifier.value = MessageStatus.read;`

After: `message.setStatus = MessageStatus.read;`

### Network image progress builder type renamed

Search: `networkImageProgressIndicatorBuilder:`, `DownloadProgress`.

The third parameter is now `CacheNetworkImageDownloadProgress` (same
`originalUrl`, `totalSize`, `downloaded`, `progress` members) instead of
`cached_network_image`'s `DownloadProgress`. Closures with untyped parameters
compile unchanged; replace an explicit `DownloadProgress` type and drop the
`cached_network_image` import if nothing else needs it.

## From < 2.5.0

### The app must dispose `ChatController`

Search: `ChatController(`, `dispose()` of the widget that owns it.

Before 2.5.0, `ChatView` closed the controller's stream and disposed its
`ScrollController`. It no longer does: dispose the controller in the
owning `State`, and don't dispose its `ScrollController` separately.

After:

```dart
class ChatScreen extends StatefulWidget {
  const ChatScreen({super.key});

  @override
  State<ChatScreen> createState() => _ChatScreenState();
}

class _ChatScreenState extends State<ChatScreen> {
  late final ChatController _chatController;

  @override
  void initState() {
    super.initState();
    _chatController = ChatController(
      initialMessageList: [],
      scrollController: ScrollController(),
      currentUser: const ChatUser(id: '1', name: 'Me'),
      otherUsers: const [ChatUser(id: '2', name: 'Alex')],
    );
  }

  @override
  void dispose() {
    _chatController.dispose(); // also disposes the ScrollController
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => ChatView(
        chatController: _chatController,
        chatViewState: ChatViewState.hasMessages,
      );
}
```

### chatview's own callback typedefs removed

Search: `VoidCallBack`, `VoidCallBackWithFuture`, `MessageCallBack`,
`StringCallback`, `ReplyMessageCallBack` used as type names in app code.

| Removed | Use |
|---|---|
| `VoidCallBack` | `VoidCallback` |
| `VoidCallBackWithFuture` | `AsyncCallback` (`package:flutter/foundation.dart`) |
| `MessageCallBack` | `ValueSetter<Message>` |
| `StringCallback` | `ValueSetter<String>` |
| `ReplyMessageCallBack` | `ValueSetter<ReplyMessage>` |

The function types are identical, so closures passed to chatview don't change.

### `PackageStrings` constants replaced by `ChatViewLocale`

Search: `PackageStrings.` (for example `PackageStrings.today`).

Before: `Text(PackageStrings.today)` (the class was not exported before 2.5.0,
so this only compiled through a `package:chatview/src/utils/package_strings.dart`
import)

After: `Text(PackageStrings.currentLocale.today)`

To translate the built-in strings, register a locale and select it. A custom
`ChatViewLocale` must supply every string except `edit`, `edited`, `editing`,
`sending`, `sent`, `read` and `notDelivered`, which have English defaults in
the latest version (see `references/2.x-to-3.0.0.md` for the 3.0.0 additions):

```dart
PackageStrings.addLocaleObject('es', spanishLocale); // a ChatViewLocale
PackageStrings.setLocale('es');
```

### Dead configuration fields removed

These fields were never read by the package. Delete them, or move them where
noted:

| Removed | Action |
|---|---|
| `ChatBubbleConfiguration.receiptsWidgetConfig` | delete, or move to `outgoingChatBubbleConfig: ChatBubble(receiptsWidgetConfig: ...)`. Moving it activates the setting (`showReceiptsIn`, `receiptsBuilder`, `lastSeenAgoBuilder`), which never applied from the removed field: ask the user first |
| `RepliedMessageConfiguration.repliedImageMessageBorderRadius` | delete |
| `RepliedMsgAutoScrollConfig.highlightScrollDuration` | delete |

Before:

```dart
chatBubbleConfig: ChatBubbleConfiguration(
  receiptsWidgetConfig: ReceiptsWidgetConfig(
    showReceiptsIn: ShowReceiptsIn.all,
  ),
),
```

After:

```dart
chatBubbleConfig: const ChatBubbleConfiguration(
  outgoingChatBubbleConfig: ChatBubble(
    receiptsWidgetConfig: ReceiptsWidgetConfig(
      showReceiptsIn: ShowReceiptsIn.all,
    ),
  ),
),
```
