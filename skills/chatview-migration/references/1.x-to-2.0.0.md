# 1.x → 2.0.0

Applies if the app is on any 1.x version (or older, after
`references/to-1.0.0.md`). The "after" code is written against the latest
chatview. Dart SDK minimum becomes 3.2.0 (latest: 3.4.0).

## Users moved to `ChatController`

Search: `currentUser:` inside `ChatView(`, `chatUsers:`, `.chatUsers`.

Before:

```dart
final chatController = ChatController(
  initialMessageList: messages,
  scrollController: ScrollController(),
  chatUsers: [ChatUser(id: '2', name: 'Alex')],
);

ChatView(
  currentUser: ChatUser(id: '1', name: 'Me'),
  chatController: chatController,
  chatViewState: ChatViewState.hasMessages,
)
```

After:

```dart
final chatController = ChatController(
  initialMessageList: messages,
  scrollController: ScrollController(),
  currentUser: const ChatUser(id: '1', name: 'Me'),
  otherUsers: const [ChatUser(id: '2', name: 'Alex')],
);

ChatView(
  chatController: chatController,
  chatViewState: ChatViewState.hasMessages,
)
```

Read users back with `chatController.currentUser`,
`chatController.otherUsers` and `chatController.getUserFromId(id)`.
`otherUsers` is read-only since 2.4.1: see `references/2.x-to-2.5.0.md`.

## `Message.sendBy` renamed to `sentBy`

Search: `sendBy` (constructor argument, field reads).

Before: `Message(message: 'Hi', createdAt: now, sendBy: '1')`

After: `Message(message: 'Hi', createdAt: now, sentBy: '1')`

Rename `message.sendBy` reads to `message.sentBy` too. The parameter names of
`SwipeToReplyConfiguration.onLeftSwipe` / `onRightSwipe` changed the same way;
closures don't need edits.

## JSON format of `Message`

Search: `Message.fromJson(`, `.toJson()`, and any backend or local storage
that stores messages in the package format.

`toJson()` / `fromJson()` were rewritten:

| Key | 1.x | 2.0.0+ |
|---|---|---|
| sender | `'sendBy'` | `'sentBy'` |
| `createdAt` | `DateTime` object | ISO-8601 string |
| `message_type` | `MessageType` object | enum `name` string |
| `status` (`fromJson`) | expected a `MessageStatus` object | parsed from the `name` string |
| `voice_message_duration` | `Duration` object | microseconds (`int`) |

`ReplyMessage` gets the same type changes (`message_type` as the enum name,
`voiceMessageDuration` as microseconds; that key keeps its camelCase name).
`Reaction` keys are unchanged. `ChatUser.toJson` gains `imageType` and
`defaultAvatarImage`.

Data saved with the old keys is read with an empty `sentBy`. Map the old key
when reading stored data, for example
`Message.fromJson({...json, 'sentBy': json['sentBy'] ?? json['sendBy']})`.
Since 2.4.1 `fromJson` also reads `update` / `update_at` (`updated_at` since
3.1.0).

## `ChatView.showTypingIndicator` removed

Search: `showTypingIndicator:` inside `ChatView(`.

Before: `ChatView(showTypingIndicator: isTyping, ...)`

After: delete the argument and set it on the controller when the state
changes:

```dart
chatController.setTypingIndicator = true; // show
chatController.setTypingIndicator = false; // hide
```

## `typingIndicatorNotifier` is read-only

Search: `typingIndicatorNotifier.value =`.

`typingIndicatorNotifier` is now a `ValueListenable<bool>`. Replace writes
with `chatController.setTypingIndicator = value;`. Listening is unchanged.

## `GroupedListOrder` is chatview's own enum

Search: `GroupedListOrder.ASC`, `GroupedListOrder.DESC`,
`package:grouped_list/grouped_list.dart`.

chatview no longer depends on `grouped_list`. Use `GroupedListOrder.asc` /
`GroupedListOrder.desc` from `package:chatview/chatview.dart`, and delete the
`grouped_list` import (and the dependency, if nothing else uses it), or the
name is ambiguous.

## `ReplyPopupConfiguration` callbacks receive the message

Search: `onMoreTap:`, `onReportTap:`.

Before:

```dart
replyPopupConfig: ReplyPopupConfiguration(
  onMoreTap: () {},
  onReportTap: () {},
),
```

After:

```dart
replyPopupConfig: ReplyPopupConfiguration(
  onMoreTap: (message, sentByCurrentUser) {},
  onReportTap: (message) {},
),
```

`replyPopupBuilder`'s second parameter is now named `sentByCurrentUser`
(closures don't need edits).

## `ChatController.dispose()` also disposes the `ScrollController`

Search: `scrollController.dispose()` near `chatController.dispose()`.

Don't dispose the `ScrollController` passed to `ChatController` yourself.
Since 2.5.0 the app must call `chatController.dispose()`; see
`references/2.x-to-2.5.0.md`. From 2.0.0 to 2.4.1 `ChatView` still disposes
the `ScrollController` and closes the message stream itself, so an app that
stops in that range must not call `chatController.dispose()` (it would dispose
the `ScrollController` a second time).

## `emoji_picker_flutter` is re-exported

`package:chatview/chatview.dart` exports all of `emoji_picker_flutter`
(`Config`, `Category`, `EmojiPicker`, …). If the analyzer reports an
ambiguous import, add `hide <Name>` to the other import. The
`emoji_picker_flutter` major version also changed in 2.3.0 (3.x) and 2.4.1
(4.x); if the app passes `emojiPickerSheetConfig: Config(...)`, check that package's changelog
for renamed `Config` fields.
